# 一次性本人历史迁移

第二阶段已实现临时迁入通道，区别于日常产品功能。个人版无账号、文件导出、备份或恢复；历史数据不进入公开源代码和网站资源。

旧系统按版本化 `PERSONAL_CUTOVER=True` 冻结业务、规则、身份资料和定时月结；登录、退出、历史查看及本人管理员签发迁移码暂保留。必须等受控发布完成再最终读取，不删旧库，不提前下线。

## 手机操作

1. 先在 Safari 打开 `https://ryanwilllo.github.io/massage-personal/`，添加到主屏幕，并从主屏幕打开该应用。已安装的应用在「应用设置」检查更新并应用到 1.2.1。
2. 在 Safari 登录旧系统的本人管理员账号，进入「管理员后台 → 迁入个人版」，取得并复制迁移码；不要将码发送到聊天或给他人。
3. 回主屏幕个人版「应用设置 → 迁入旧记录」，粘贴迁移码并点「读取并核对旧记录」。迁移码 15 分钟有效，失效可重新取得。
4. 核对页面中的月份、记录数、明细数、收入和计薪分钟，确认属于本人，再点「确认是本人记录，保存到手机」。
5. 页面必须显示「迁入完成，重新打开数据库核对通过」。关闭并重新打开主屏幕应用，查看历史月份和记录，确认仍在。保存后中断时回迁入页点「完成保存核对」，不必重新下载。

必须在实际日常使用的主屏幕应用内迁入。不同设备、浏览器或网址不能保证共享数据库，不能将 Safari 标签、localhost 或另一个预览来源的结果视为主屏幕应用验收。

## 私密传输与保护

迁移码仅存页面内存，用户主动复制粘贴；不置于 URL、Git、日志或浏览器存储。个人版仅在迁入时向旧站发带 Authorization 的 GET，不带 Cookie；旧站专用只读码校验签名、用途、目标来源、时效、当前认证版本和本人管理员账号状态。CORS 只允许正式 GitHub Pages 来源，不提供通用外部账号认证。

单个旧库 WAL 读取事务包含本人 completed 服务和关联明细、公共项目及全部有效规则版本，排除同事服务、账号、绑定姓名、密码、凭证、规则备注和结算文件。本人 processing 记录会阻止迁移；cancelled 记录不属于有效收入历史，不迁入。保留金额、计薪分钟、时长、规则编号和源记录/明细编号，不按现价重算。下一本地编号取最大值加一。旧 addon_time 可保留历史显示，录入和管理入口继续停用。

响应提供精确 wire 和 SHA-256、逐月记录/明细数量、收入、计薪分钟。手机先验证结构、关联完整性、编号唯一、逐单快照汇总、哈希和月汇总。仅初始空库允许一个事务保存；已有记录、规则修改或既有迁入标记都拒绝覆盖。重复和并发迁入只能成功一次，空历史也留标记。

保存完成后关闭并重新打开 IndexedDB，比对全部项目、规则、服务和明细哈希以及逐月结果；通过前阻止日常写入。中断可从保存的标记重新核对。通过后设置页隐藏迁入入口，标记继续防重复导入。

迁移码有效期内可重试读取冻结数据。只有程序进入离线缓存，跨来源迁移响应不缓存；前端 CSP 临时只增加旧站连接许可。迁移完成且用户确认 iPhone 持久化后，撤除临时代码/CSP 许可和旧站通道，再执行旧系统下线。

## 验收边界

自动测试覆盖真实旧后端合成 wire、持久化、月汇总、快照、损坏数据、空库保护、规则修改保护、并发/重复、编号续接、中断恢复及零历史。公开测试 fixture 仅为合成数据，不是本人历史。

自动测试和发布成功不代表本人已在 iPhone 迁入。实机结果、实际逐月数字和关闭重开后的持久化，需要上述用户手机操作确认；完成前保留旧只读系统。
